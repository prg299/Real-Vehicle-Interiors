# Vehicle expansion

`MELens_Utilities.lua` runs appliance updates only for owners exposing vehicle-level `getModData`. Build 42.21 also invokes part callbacks on an unloaded `VirtualVehicle`, whose API exposes parts but not that state. The shared capability gate leaves generator, stove, fridge and heater state unchanged on that proxy; normal updates resume when a full vehicle is loaded. It introduces no save migration or new part/item IDs.

The native regression in `dev/virtual-streaming-tests.py` targets the Chevrolet painting-services step van, observes actual virtual-owner part scheduling, checks two chunk unload/reload cycles and compares original cargo, interior storage, furniture IDs, capacities and utilities. Its cold-load mode verifies the same saved vehicle in a fresh process. Gameplay errors fail the test; external startup diagnostics remain in the retained logs. The shared state snapshot skips vanilla's invalid seat-capacity query while virtualized and requires those capacities to match again after loading.

The expansion adds 193 vehicle definitions to the 10 already supported: **203 total** on Build 42.21. Variants share a layout only when their resolved body mesh and model scales match.

Install any combination of supported vehicle packs, with each pack's own dependencies, and enable them before Real Vehicle Interiors. Missing packs are skipped. Explicit aliases handle shortened vanilla and KI5 business names. Generic freight receives native parcels; specialist roles use their matching native procedural distributions and small guaranteed starter quantities. The shared storage code adds those supplies first and rejects additions beyond the container's capacity. Original vehicle cargo remains separate from the new furniture's inventory.

These fittings use the shared furniture placement, storage and resting systems. SWAT seats reuse the released passenger IDs. The generic delivery step van has three cargo positions on each wall, with a clear centre aisle; specialist variants use their own programme. Open shelf models contain no decorative stock: actual items in their containers are packed onto the measured boards using their native world models and sizes. Removing or adding items changes the display. Oversized items and contents beyond the normal loose-item drawing budget remain accessible in storage. The same display supports the original shelf unit, while libraries use the equipment rack's real storage capacity. The new 0.90 × 0.40 × 0.78 m workbench has capacity 30 and an empty authored top for the actual stored tools or radio items.

Factory slots are appended after released slot IDs; existing slot coordinates and passenger IDs stay stable. A one-time layout stamp identifies untouched new vehicles. Cleared or player-furnished vehicles retain their saved layout, and empty factory slots serialize with a harmless repair placeholder, preventing repair or reload from refurnishing them. Factory seats reuse the existing furniture seat IDs rather than reducing the engine's remaining standing-seat budget.

Floor freight uses the same fresh-vehicle stamp. `MELens_Parts.createFloor` adds ordinary items to the Floor container and records their positions through `MELens_Loose`; `initFloor` preserves loaded inventory, including an empty looted floor. The server owns creation, both furnishing/loot sandbox options apply, and placement and capacity checks can reject stock. There is no separate decorative copy or new cylinder furniture.

Smaller vans fit a bed along one wall and a kitchenette across the front, with a clear aisle beside the bed. Wider vehicles have places on both sides. Placement checks the furniture's actual footprint and rejects genuine overlaps. Where alternative markers overlap, the pointer selects the nearest marker centre. Promotional captures use actual factory fittings, without adding a bed and kitchen to every vehicle.

The F700 box truck also accepts a bed and kitchenette along the same wall after clearing the cargo in their footprints. A bed is 1.5 m wide, a kitchenette 1 m, and a cargo box 0.5 m: adjacent highlights are possible positions, not always separate rooms for two pieces. Remove stacked boxes from above before clearing the boxes below.

Stock vehicles retain their native paint masks while inside, and road wheels keep their original rendering. Wheel-housing lids remain opaque when the camera-facing wall is cut; the vanilla step van now has measured rear-wheel housings too. Cargo interiors use worn grey diamond-plate metal flooring; campers retain their wood floors and buses their rubber flooring. An opaque full-height partition closes the cab behind every cargo cutaway, including the F700 box, bank and SWAT trucks. This partition stays intact at every wall-height setting. Each profile resets the previous vehicle's optional cab-height limit. Shared clipping rules inventory every variant's factory models, including custom rear chairs, liners and roof accessories, while preserving the cab ahead of the compartment.

These are physical interiors inside the vehicle body, with dimensions measured from the installed model. They do not use separate map rooms. The Arcadia RV Interior coverage list was used to identify candidate vehicles; its scripts, room maps and assets are not included. Livestock/Animals support remains separate on `animals-support`.

Cargo rear closures follow the measured body cross-section, including rounded corners. Both faces render; a thin frame remains when the real door is open or removed. Static side returns join the surviving lining edges to that frame. Rear frame depth follows the connected side-pillar contour at each measured height and stops where it turns across the rear body; a central rear-body projection cannot set the whole frame's depth. Depth is capped at the measured height range rather than extrapolated into an unmeasured skirt or roof. The original thin front skin still spans the full closure. The aft leaf surface shares the front leaf's visibility state. A narrow metal threshold fills the space between the existing floor edge and the rear leaf without overlapping the floor or changing the navigation outline. Removing the leaf leaves the doorway centre open. The closure shares the shell's material and wall cutaway, and opening boundaries split wall segments on both axes. Vanilla cargo, passenger, ambulance and radio vans have enlarged rear-wheel housings; their usable centre aisles remain clear. Re-arming the cutaway also clears the previous camera-wall state when wall options change.

Additional door linings use measured `doorLinings` regions in the vehicle spec. The shell generator splits wall segments at each region and exports a separate, double-sided panel using the existing wall material. The profile's `shell.extraDoors` maps each model index to its real vehicle part; `MELens_Parts.lua` updates and recovers those bindings independently of the primary rear door. The F350 uses this for `DoorRearRight`: the closed side door is solid from either camera side, while opening or removing it hides its lining. A measured lower step, capped floor-edge riser and jamb returns join the raised floor to the native door aperture; these stay with the body when the door opens. Original shell model indices stay stable.

Factory placement bays can start bare through the spec's `factoryEmpty` role/wall/piece selection. Those bays retain their slot IDs, dimensions and accepted furniture. The F350 ambulance's two side-door medical-shelf bays use this setting. Initial defaults do not delete installed player furniture or stored items from existing saves.

Cab measurements include the representative vehicle's resolved side panels and doors where they share the body FBX. Only numerical sections are retained. The partition follows those sections at each height, including trim steps, rather than filling a convex outline across them. Its two skins and edge returns seal the native cut; measured depths on the radio van and F350 cover the original cab surfaces that project into the compartment. Open wall UVs stay within the atlas's plain lining area.

The Java renderer exposes independent cut offsets for native body surfaces away from the camera, body surfaces facing the camera, and native door leaves. These offsets lower an exposed native edge beneath the authored lining while respecting a floor limit. Authored shell pieces retain their own cuts, furniture remains intact and road wheels retain their original rendering. `MELens_Cabin.lua` converts distances through the profile's mesh scale. Cargo uses 0.10/0/0.16 m for far/near/door surfaces, limited to 15 mm above the floor; campers and buses retain zero offsets. `dev/rear-door-tests.py --cut-inset-presets` compares independent settings at fixed cameras and restores zero afterward.

The vanilla ambulance opts into a grey finish for its exposed dark native inner body returns. The shader selects their neutral texels, non-paintable alpha and white part mask within the cargo bounds, excluding wheels and lamp masks. The exterior red/white paint uses a different native mask. Other profiles leave this finish disabled: the radio van uses a similar dark mask for legitimate exterior trim. A new cutaway resets both this optional finish and the native cut offsets, preventing one vehicle's settings from leaking into another.

Original trailer corner joins can opt into `cornerReturns`, traced from connected native body sections at their real vertex heights. The added skins bridge angular-sampling corner chords without changing the lining, floor, navigation or furniture coordinates. The B700 uses a separate low `cowlReturn` traced from its native cowl section; its front protection stops below the windshield posts. Both additions reuse the existing wall material and cutaway behavior.

`bodyKeepPlanes` contains per-profile model-alias planes in body space. It trims the Scamp spare wheel's narrow inward projection while accounting for the different Scamp13/16 model translations. A separate measured rear-bumper plane keeps its brace below the floor; fixed-camera controls distinguish that brace from the body and spare. `MELens_Profiles.lua` records the exact registered global defaults; `MELens_Cabin.lua` restores touched aliases before switching profiles, on exit and at game/menu boundaries. Untouched aliases keep their existing settings. The Scamp wheel covers also follow measured native tyre crowns rather than a shared assumed height. The B700's measured windshield-frame mask removes the remaining upper mullion while retaining its low cowl and driver chair.

`MELens_Java.lua` owns the shared `MELens.java()` readiness gate. An exposed table alone does not establish that the matching Java file loaded: keep planes, seat binding, cutaway control and model-binding inspection/cleanup must be callable. An incomplete API skips Java-specific startup calls and model declarations, keeps the same safe part order and rejects interior entry through the existing no-Java message. The console identifies the missing method and asks for an update, Java approval and restart. The check accepts a bridge populated later; it does not permanently cache a failed startup. A Java-free server retains the existing shared inventory/seat definitions.

Native model visibility is separate from saved furniture. `RV.isPartModelVisible` checks the actual binding to the current live `VehiclePart`; `RV.clearStalePartModels` removes superseded bindings only for this mod's same-named shell/furniture part. `MELens_Parts.showPiece` validates the desired model despite a cached selection, and `refreshShell` restores missing floor/wall bindings from the existing quarter-second client refresh. The rear leaf still follows the real open/missing-door state. Superseded UI part references are rejected, and transient visibility/preview caches use weak keys. Recovery never calls furniture creation or loot initialization and never replaces inventory or utility state.

## Rebuilding the expansion

The ordinary build uses the checked-in profiles, walk grids and authored shell mesh. Regenerating them requires the game and vehicle packs above, Blender 3.6, Python, and the read-only Arcadia Workshop reference `3773972040`. Run the following tools in order through the machine's resource guard:

1. `tools-src/vehicles/catalogue.py` resolves the installed coverage and external assets into ignored `build/rv` metadata.
2. `tools-src/vehicles/prepare_expansion.py` groups matching body meshes and scales.
3. Blender runs `tools-src/blender/measure_fleet.py -- build/rv/floorplans/fleet-measures.json` to measure compartments and the cab cross-section used to close each cut face, recording the body/panel/door contributors.
4. `tools-src/vehicles/build_expansion.py` generates layout specs, profiles and model declarations. Its shared `factory_layouts.py` module appends role-specific fitouts and validates measured footprints and the character's aisle clearance.
5. Blender runs `tools-src/blender/rv_kit.py -- mod/RealVehicleInteriors/common/media --shells-only --shell-file=MELens_Fleet` with every generated `shell_<family>.json` config in the coverage file.
6. `tools-src/vehicles/vision_geometry.py --floorplans <directory>` exports the sight openings to `MELens_VisionGeometry.lua`. Repeat `--floorplans` for directories holding the original and expansion measurements and resolved script JSON. The ordinary build uses this checked-in numerical metadata.

Blender's binary FBX importer handles most models. The vanilla step van uses ASCII FBX; install the `ufbx` Python wheel matching Blender's bundled Python into `.tools/ufbx-blender`, or set `RVI_UFBX_DIR`. This tool dependency and all external vehicle geometry stay outside the shipped mod. New shells reuse the existing F700 wall/floor materials.

Within `factory_layouts.py`, `role_for` resolves script identities and ordered business aliases, `ROLE_SUPPLIES` declares native distributions and starter items, `use_for` separates workstation, seat, cold-storage and packing inventory, and `layout` places shared furniture within the measured body. `append_profiles` preserves the released slots and appends the factory programme with the existing `cargo-service-1` stamp. Optional `factoryFloor` positions describe native floor freight. Furniture dimensions/models, native item display and shared interaction remain owned by the kit and runtime modules. `tools-src/regression/factory-roles.lua` checks generated role assignments, required fittings, real starter inventory and the absence of freight in passenger areas.

`MELens_Loose.list` reuses free matching-type `factoryFloor` bays when inventory transfers return unpositioned freight. Declared full envelopes must fit the current lining and avoid installed furniture, wheel wells and other known freight. This shared calculation creates no items and does not alter explicit player placements or saved position records. Unknown mixed floor-item footprints retain the existing generic fallback; its arbitrary-size packing is not established by this feature.

At world initialization, shared Lua registers the room rings and sight openings with the Java component. Sight and indoor panic share the registered interior-seat classification. The native zombie sight adapter adds wall occlusion; hearing, target memory and attacks remain owned by the game. Stock windows embedded in the body model use the vehicle script's interaction area as their opening estimate.
