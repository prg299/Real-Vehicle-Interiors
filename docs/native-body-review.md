## F350 findings to carry forward

* Use the installed vehicle's actual hull, animated door leaves and glazing. Do not copy dependency geometry. Classify doors and windows by their vehicle-part contracts; similarly named armor is a separate part. Missing or destroyed windows and removed parent doors must not leave panes floating in the aperture.
* Separate the fallback lining and its full-height doorway returns from low steps, utility fittings and wheel surfaces before hiding it. Append model bindings so released indices keep their meaning. Missing optional Java support must restore the complete fallback.
* Cut the native hull, leaves, glass and surviving supports at the same physical height. Scope two-sided rendering to the mesh draw and restore culling afterward. Character depth must come from a body draw that actually completed, rather than a skipped lining.
* Measure each body's wheel openings. The F350 contour and rear sill are not fleet defaults. Reciprocal masking must cover both the interior floor and the far inward arch wall; floor-only masking left a tread crescent. Visual infill must not silently enlarge navigation or furniture bounds.
* Measure furniture in three dimensions, including its back trim. The F350 front cabinet anchors at z=-0.40 crossed the native bulkhead. Moving only slots 7/8 to -0.46 leaves about 16.6 mm clearance while preserving slot identity and contents. Other bodies need their own clearance assessment.
* Preserve saved fixtures by SQL identity before invoking spawn helpers, which may delete the preceding test vehicle. Save synchronously and confirm state in a fresh process. The historical B snapshot's IDs were absent from the supplied disk save; that snapshot is not preservation evidence. The intact older SQL 6 vehicle and a separately marked nonzero-utility fixture are the actual continuity fixtures.
* Select a loaded, unobstructed capture pad. Frame the entire body for exterior comparisons and use additional close views for openings and furniture. Do not treat a cropped bumper or obstructed frame as a complete side audit.
* Confirm the full native script inventory after loading the save. A test profile's default enabled mods do not replace the mod list stored in an existing world. The fleet pilot caught 28 missing Chevy variants before any captures. Dependency synchronization is confined to the explicitly selected disposable save copy.
* Review original native frames at all four headings and three wall heights, with camera walls on/off and doors closed, open, missing and restored. Real keyboard entry/exit proves input paths; scripted door states prove renderer fixtures only. Build, save, image review and human acceptance are separate results.
* Inventory each part's actual rendering path. Stock van rear doors and hoods are embedded body-mask regions with no separate animated leaves. Unchanged open-state stills do not prove animation; missing/restored masks still need a visible aperture. Source bodies also contain real inward-facing polygons, so reverse GL winding alone cannot classify their interior finish.
* Inspect empty-interior controls as well as furnished views. Crates, shelves and benches can conceal a bad floor/arch join. Diagnostic furniture hiding changes draw clipping only and restores the entire keep-plane map; item IDs and contents must still match afterward.
* Resolve mask ownership on the actual source. The passenger van paints its middle doors with the fixed side's blue/yellow mask. Door/window mask slots clear the pane but cannot distinguish the lower door from the whole side. Its measured door bounds need an explicit part-keyed opening instead.
* Project diagnostic points using the physical vehicle base from `getWorldPos(0,0,0):z()`, as production picking does. `getZ()` omits the raised body position and displaced the first projected points. Existing images remain valid, but those early point receipts are excluded.

The F350 evidence is indexed in `build/rv/f350-refine-20261024/review.json` and `build/rv/f350-front-spots-20261024/review.json`.
